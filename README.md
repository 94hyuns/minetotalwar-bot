# 영지전 디스코드 운영 봇

설계 문서 `docs/설계.md` §33 의 봇입니다. 모드 서버가 쓰는 `export/factions.json`·`export/status.json` 파일만 읽고, GitHub 이슈는 REST API 로 다룹니다.

## 하는 일

| 채널 / 명령 | 동작 |
|---|---|
| #버그제보 | `BUG_PRIVATE=true`(기본): 새 글 → **비공개 스레드** "#번호 · 작성자 · 첫 줄 요약"(작성자만 초대, 초대 불가) → 본문·첨부를 다시 받아 스레드 첫 메시지로 옮김(첨부가 업로드 한도·25MB 를 넘으면 링크) → **원글 삭제** → GitHub 이슈(라벨 `버그`, 첨부 주소는 스레드의 것) → "접수 #번호". 봇이 꺼져 있던 동안 채널에 남은 사람 글(최근 50개)은 기동 때 같은 절차로 처리. `BUG_PRIVATE=false` 면 원글에 공개 스레드(건의와 같은 방식) |
| #건의사항 | 원글에 **공개** 스레드 + 이슈(라벨 `건의`) — 서로 보고 👍 를 누를 수 있게. 하루 한 번 원글의 👍 수를 이슈 본문 첫 줄 "추천 N" 으로 갱신 |
| (이슈 상태) | 5분마다 확인. 라벨 `확인중` → 스레드에 "확인 중", `보류` → "보류 (관리자 확인 필요)". 닫히면 버전이 있으면 "수정됨 v1.0.xx", 없으면 "처리됨"(버전은 `v1.0.xx` 라벨 또는 댓글에서 찾음) → **스레드 잠금·보관**. 다시 열리면 잠금 해제 |
| (중계) | 대응된 스레드에 사람이 답글을 쓰면 이슈 댓글 "**디스코드 이름**: 내용 + 첨부" 로 옮김. 이슈에 새 댓글이 달리면 5분 안에 스레드에 "GitHub 댓글 (작성자): 내용"(1,900자 넘으면 자르고 링크) |
| #세력순위 | 고정 메시지 하나를 `factions.json` 이 바뀔 때마다(2분마다 확인) 편집 |
| `/서버상태` | 접속자·MSPT·게임 날짜·시즌 D-day·침공·요새 수. `status.json` 이 3분 넘게 안 바뀌면 "서버가 꺼져 있거나 응답 없음" |
| `/점수 [세력]` | 점수판 상위 5 + 지정 세력의 점수 구성(보유·토벌·전쟁·재위) |
| `/가이드 갱신` | 관리자만. 가이드 파일을 `##` 절마다 메시지 하나로 #게임설명 에 올리거나 제자리 편집. `UPSTREAM_REPO` 가 있으면 마지막에 "모드 버그는 여기로" 링크 |
| `/제보 목록 [버그\|건의]` | 관리자만. 열린 이슈를 추천 수(건의 = 본문 "추천 N", 버그 = 원글 👍)·오래된 순으로 요약 (번호·제목·추천·며칠 전·라벨) |
| `/상류` | 관리자만, 제보 스레드 안에서. 그 이슈를 `UPSTREAM_REPO` 에 같은 제목·본문으로 열고 스레드에 번호를 남김. 이슈에 라벨 `상류` 를 붙여도 같음(5분 안에) |
| (주간 집계) | 매주 월요일(한국 시간) `NOTICE_WEBHOOK` 으로 "이번 주 제보 (지난 월~일): 열린 제보 N건 · 처리 M건" 한 줄 |

#서버공지 의 게임 공지는 모드의 웹훅이 직접 올립니다. 봇은 주간 집계만 같은 웹훅(`NOTICE_WEBHOOK`)으로 보냅니다.

### 운영 모드 `BUG_MODE`

- **`list` (기본)**: 버그도 건의처럼 이슈 + 스레드 "접수 #번호" 까지만. 운영자가 시간 날 때 GitHub 이슈 탭에서 처리하고 닫으면 스레드 알림은 그대로 갑니다. `/제보 목록`·주간 집계로 정리하세요.
- **`auto`**: 접수 답글이 "접수 #번호 — 자동 처리 중" 으로 바뀌고, 실제 처리는 운영자의 Claude Code 세션이 합니다(아래 "Claude 세션 연결"). 봇 동작은 그 밖에 같습니다.
- 건의는 두 모드 모두 목록만(자동 처리 없음).

## 1. 디스코드 봇 만들기

1. https://discord.com/developers/applications → New Application → 왼쪽 **Bot**.
2. **Reset Token** 으로 토큰을 받아 `.env` 의 `DISCORD_TOKEN` 에 넣습니다(남에게 보이지 않게).
3. 같은 Bot 화면의 **Privileged Gateway Intents** 에서 **Message Content Intent** 를 켭니다. (꺼져 있으면 제보 글 본문이 빈 채로 옵니다.)
4. 왼쪽 **OAuth2 → URL Generator**: Scopes 에 `bot`, `applications.commands`. Bot Permissions 에 아래를 체크하고 나온 주소로 서버에 초대합니다.
   - View Channels (채널 보기)
   - Send Messages, Send Messages in Threads
   - Create Public Threads (#건의사항)
   - **Create Private Threads** (#버그제보 비공개 스레드)
   - **Manage Messages** (#버그제보 원글 삭제)
   - **Manage Threads** (비공개 스레드 모두 보기, 이슈가 닫히면 스레드를 잠그고 보관, 다시 열리면 풀기)
   - **Read Message History** (메시지 기록 보기: 👍 수, 기동 때 남은 글 처리)
   - **Attach Files** (제보 첨부를 스레드로 다시 올리기)
   - Read Message History
   - 반응 추가 권한은 필요 없습니다(👍 수는 메시지 기록으로 읽음).
5. #서버공지·#세력순위·#게임설명 은 일반 멤버의 쓰기 권한을 끄고, 봇 역할에는 쓰기를 허용하세요.
6. **#버그제보 채널 권한** (`BUG_PRIVATE=true` 일 때)

   | 대상 | 메시지 보내기 | 메시지 기록 보기 | 비공개 스레드 만들기 | 메시지 관리 | 스레드 관리 | 파일 첨부 |
   |---|---|---|---|---|---|---|
   | @everyone | ✓ | **✗** (지우기 전 잠깐 보이는 것 방지) | ✗ | ✗ | ✗ | ✓ |
   | 봇 역할 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
   | 운영자 역할 | ✓ | ✓ | — | — | ✓ (모든 제보 스레드를 봄) | ✓ |

   제보자는 초대된 자기 스레드만 보고, 스레드 안에서는 답글·첨부를 쓸 수 있습니다. 비공개 스레드는 서버 부스트와 관계없이 쓸 수 있습니다.

## 2. 채널 ID 얻기

디스코드 설정 → 고급 → **개발자 모드** 켜기. 그다음

- 서버 아이콘 우클릭 → **서버 ID 복사** → `GUILD_ID`
- 각 채널 우클릭 → **채널 ID 복사** → `CHANNEL_BUG`, `CHANNEL_SUGGEST`, `CHANNEL_RANKING`, `CHANNEL_GUIDE`

## 3. GitHub 토큰

GitHub → Settings → Developer settings → **Fine-grained tokens** → 저장소 `94hyuns/minetotalwar-bot` 만 선택, Repository permissions 에서 **Issues: Read and write** (Metadata 읽기는 자동). 토큰을 `GITHUB_TOKEN` 에 넣습니다. 봇이 처음 뜰 때 `버그`·`건의`·`확인중`·`보류`·`상류` 라벨이 없으면 만듭니다.

## 4. 설정 파일

```bash
cp .env.example .env
nano .env
```

| 키 | 설명 |
|---|---|
| `EXPORT_DIR` | 모드가 내보내는 폴더 (기본 `../minetotalwar/export`) |
| `GUIDE_PATH` | 가이드 파일. 저장소에서 돌리면 기본 `../docs/가이드.md`, 운영 서버는 배포 스크립트가 복사한 `./가이드.md` |
| `STATE_PATH` | 상태 파일 (기본 `./state.json`). 이슈↔스레드 대응과 메시지 ID 가 들어 있으니 지우지 마세요 |
| `BUG_MODE` | `list`(기본) 또는 `auto` |
| `BUG_PRIVATE` | `true`(기본) = #버그제보 를 비공개 스레드로 옮기고 원글 삭제, `false` = 원글에 공개 스레드 |
| `NOTICE_WEBHOOK` | #서버공지 웹훅 주소 (주간 집계). 비우면 안 보냄 |
| `UPSTREAM_REPO` | 모드 제작자 공개 이슈 저장소 `owner/name`. 기본값 `94hyuns/minetotalwar-bot`(영지전 모드 공개 이슈 저장소). 빈 값으로 두면 `/상류`·라벨 `상류` 꺼짐 |

**상류 저장소 권한 주의**: 상류 이슈도 같은 `GITHUB_TOKEN` 으로 엽니다. fine-grained 토큰이면 그 저장소도 선택하고 Issues 쓰기를 줘야 합니다(남의 공개 저장소라면 classic 토큰 `public_repo` 범위가 필요할 수 있음). 상류는 공개이므로 봇이 본문에서 "디스코드 작성자·원문 링크" 꼬리와 "추천 N" 줄을 빼고 "원 제보: 서버 이슈 링크" 를 붙여 보냅니다. 서버 이슈 저장소가 비공개면 그 링크는 상류 쪽 사람에게 열리지 않습니다. 첨부 이미지(디스코드 주소)는 그대로 갑니다.

상대 경로는 `bot.py` 가 있는 폴더 기준입니다.

## 5. 운영 서버에서 실행 (tmux 세션 `mtwbot`)

보통은 Windows 에서 `tools/deploy_bot.ps1` 한 번이면 복사 · 가상환경 · 패키지 설치 · 재시작까지 됩니다. `.env` 와 `state.json` 은 복사하지 않으니, 처음 한 번은 서버에서 `.env` 를 직접 만드세요.

손으로 할 때:

```bash
cd ~/minetotalwar-bot
python3 -m venv .venv                 # 처음 한 번 (python3-venv 패키지 필요)
.venv/bin/pip install -r requirements.txt
tmux new-session -d -s mtwbot '.venv/bin/python bot.py'
```

- 로그 보기: `tmux attach -t mtwbot` (빠져나오기 `Ctrl+B` 다음 `D`)
- 멈추기: `tmux kill-session -t mtwbot`
- 재시작: 멈춘 뒤 위 `tmux new-session` 줄 다시

봇이 뜨면 슬래시 명령을 `GUILD_ID` 서버에 바로 동기화합니다(전역 등록이 아니라 즉시 보임).

## Claude 세션 연결 (BUG_MODE=auto)

`auto` 는 버그 제보를 운영자의 **Claude Code 세션**이 가져가 재현·수정·배포까지 하는 방식입니다(소규모 지인 서버용). 봇은 접수·중계만 하고, 처리는 세션이 GitHub 이슈를 보고 합니다.

**전제** (없으면 `list` 로 두세요)
- 모드 소스 저장소와 빌드 환경(JDK, `gradlew build`, 개발 서버 `tools/restart_dev.sh`·`tools/rcon.py` 가 도는 PC)
- 모드팩 배포 경로: 모드팩 저장소의 `tools/release.ps1` (GitHub CLI 로그인 포함)
- 운영 서버 ssh 접속과 재시작 경로 (우리 서버: `ssh ubuntu-server`, `~/minetotalwar`, tmux 세션 `mtw`, `start.sh`)
- 같은 GitHub 저장소 이슈에 쓸 수 있는 `gh` 로그인 또는 토큰

**켜는 법**
1. Claude Code 를 **모드 저장소 폴더**에서 엽니다.
2. "docs/운영-제보처리.md 를 읽고 그대로 따라 줘" 라고 해서 절차서를 읽게 합니다.
3. `/loop 30m 열린 버그 이슈 처리` 로 30분 반복을 켭니다. 데스크톱 앱이 켜져 있는 동안만 돕니다.

- 세션이 재현에 필요한 걸 이슈 댓글로 물으면 봇이 제보 스레드에 "GitHub 댓글 (…)" 로 올리고, 제보자의 스레드 답글은 이슈 댓글로 돌아갑니다.
- 설계가 바뀌는 수정(수치·규칙 변경)이나 재현이 안 되는 건 라벨 `보류` + 질문 댓글로 운영자에게 넘깁니다. 스레드에는 "보류 (관리자 확인 필요)".

## 처음 한 번 할 일

- 디스코드에서 `/가이드 갱신` 을 실행해 #게임설명 에 가이드를 올립니다. 가이드를 고친 뒤 배포하고 다시 실행하면 같은 메시지들을 제자리에서 편집합니다(절이 늘면 새로 올리고, 줄면 남는 걸 지움). 누가 중간 메시지를 지웠으면 전부 지우고 다시 올립니다.
- #세력순위 는 `factions.json` 이 생기면 자동으로 첫 메시지를 올리고 그 뒤로는 편집만 합니다. 메시지를 지우면 다음 갱신 때 새로 올립니다.

## 알아 둘 점

- 비공개 접수는 원글을 지우므로, 다시 올리지 못한 큰 첨부의 링크는 곧 열리지 않을 수 있습니다(제보자에게 스레드에 다시 올려 달라고 하세요).
- 원글 삭제 전에 봇이 죽으면 다음 기동 때 만들다 만 스레드를 지우고 처음부터 다시 접수합니다.
- 디스코드 첨부 파일 주소는 시간이 지나면 만료됩니다. 이슈 본문의 이미지가 나중에 안 보이면 스레드의 원문 링크로 보세요.
- 이슈를 다시 열었다가 닫으면 닫힘 알림을 한 번 더 보냅니다. `확인중`·`보류` 라벨도 뺐다가 다시 붙이면 다시 알립니다.
- 봇이 옮긴 디스코드 답글은 이슈 댓글 끝에 숨은 표식 `<!-- from-discord -->` 이 있어 스레드로 되돌아가지 않습니다. 같은 GitHub 토큰으로 다는 운영 댓글("확인 시작", "수정됨 v1.0.xx")은 표식이 없으니 그대로 스레드에 올라갑니다.
- 이슈 댓글은 마지막으로 옮긴 댓글 id 를 `state.json` 에 기억합니다. 이 기능 전에 접수된 이슈는 그때까지의 댓글을 건너뛰고 새 댓글만 옮깁니다.
- 닫힌 이슈에 댓글이 달리면 스레드를 잠깐 풀어 올린 뒤 다시 잠급니다.
- 오류는 전부 표준 출력(tmux 창)에 기록되고, 한 작업이 실패해도 봇은 계속 돕니다.
